# MathOCRClaw 工作流优化实施与负样本验证报告

日期：2026-08-25

## 1. 本轮目标与统一输出契约

本轮修改严格采用 benchmark 金标准的内容边界，并将 API1、API2、最终 Markdown 和评分候选统一到同一语义：

1. 选择题只输出最终保留的选项字母，不输出计算、排除痕迹、图上批注或其他草稿。
2. 填空题只输出每个空的最终值、公式和必要单位，不输出推算草稿。
3. 解答题、证明题和开放题输出完整的正式解题过程与结论；无答案的小问必须显式保留 `_未识别到手写答案。_`。
4. 最终交付以 Markdown 编译结果为准，JSON 不再只是旁路信息，而是最终 Markdown 和评分候选的结构化来源。
5. 题型优先根据印刷题干结构判断，检测器标签和模型自报题型仅作为次级证据。

## 2. 已完成的工作流调整

### 2.1 两次 API 使用相同内容标准

`benchmark/prompts/extract_v2.txt` 已明确区分选择、填空和解答题：选择/填空仅保留最终答案，解答题保留完整正式过程；同时强化了空白小问、教师批改痕迹、作废内容和 LaTeX 自检规则。

API2 的最终复核提示词采用同一内容契约，并强制返回：

- `question_type`；
- `section_heading_before`；
- `answer_parts[].transcription`；
- `answer_parts[].final_answer`；
- `answer_parts[].status`。

### 2.2 JSON 驱动的答案规范化

工作流现在按题型确定性地消费 `answer_parts`：

- 选择题从 `final_answer` 提取严格的 A—D 选项集合，并删除顶层草稿；
- 填空题按小问顺序保留全部 `final_answer`，逐项恢复 `$...$`；
- 解答题按 `answer_parts` 顺序渲染正式过程，并将 `no_answer`/`unreadable` 转为稳定的 Markdown 标记；
- API2 整题漏回时，按题号从 API1 JSON 恢复该题，并记录 `restored_question_from_first_pass`；
- API2 输出题目顺序变化时，先按题号匹配上下文，不再只依赖数组下标。

### 2.3 Markdown 单调保护与 lint

新增的本地保护规则会在写出 `result.md` 前检查：

- 空题干和 `[无法识别]` 哨兵是否被删除；
- 选项、小问编号、①—⑩ 和 `<插图>` 是否减少；
- `$` 定界符是否平衡；
- 解答过程的 LaTeX span 是否发生可疑减少；
- 填空最终值是否缺少数学定界符；
- 空白小问是否在最终 Markdown 中消失。

发现退化时优先回滚相应字段到 API1，而不是接受 API2 的整页自由重写。执行过的保护动作写入 `question_review.lint_actions`，便于逐题追溯。

### 2.4 题型与评分口径统一

`benchmark/scoring.py` 已改为：

- 先从题干中的选项组、横线/空位等结构判断题型；
- 选择题严格解析最终选项行，不再扫描草稿中的变量 `a`、`b`、`c` 或函数名；
- 选择/填空优先评分 `answer_parts[].final_answer`；
- 多空填空按顺序评分全部结构化最终值；
- 解答题按结构化小问重建完整过程和空白状态；
- 大题标题从上一题答案中剥离，API1/API2 执行相同的章节边界规则。

上述口径已经同步写入 `benchmark/EVALUATION.md` 和 `benchmark/README.md`。

- 选择/填空草稿清除；
- 多空填空全部最终值保留；
- 解答题空白小问显式渲染；
- `[无法识别]` 与 ④ 删除保护；
- API2 漏整题后按题号恢复；
- 大题标题不污染上一题；
- 题型由题干而不是答案草稿决定；
- 评分器使用结构化最终答案。

新旧调用的 API1 文本并不完全相同，因此不能直接用跨运行绝对分衡量 OCR 内容提升；应重点比较每次运行内部的 API1→API2 是否退化。

具体结果：

- 旧 API2 将 `16. [无法识别]`、`17. [无法识别]` 改成了 `16.`、`17.`，导致两题题干同时崩溃。
- 新 API2 的第 16、17 题都保留了 `[无法识别]`；两题 JSON 均记录 `lint_actions=["restored_unreadable_stem_sentinel"]`。
- 第 17 题完整保留 (1)(2) 解题过程，根式仍为 `$2\sqrt{30k}+205$`，没有退化为 `$2\sqrt{30}k+205$`。
- API2 相对 API1 的题干、答案、结构、状态和公式 span 均未降低，旧测试最大单页回归 `-22.84` 已被消除。

仍存在的内容误差也必须如实说明：本次 API1/API2 都把第 16 题的 `$x^2-x$` 识别为 `$x^2-3x$`，并且第 17 题一个根的符号与金标准有出入。API2 本次没有修正这两处，所以新结果是“消除二次退化”，不是“该页 OCR 已满分”。此外，本页布局检测没有形成可靠题目框（`Q=0`），工作流使用了整页证据回退并成功完成两次 API 调用。

为验证 JSON 最终答案投影，复用 2026-08-20 的 `qwen3.7-plus` 网络产物，只运行新的确定性评分器，不重新调用模型：
